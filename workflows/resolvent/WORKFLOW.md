# Resolvent workflow 1.0.0

These live references serve installed client protocol 1.0. The installed intent,
privacy, destination and review boundaries always apply; this document grants no
permissions. Retain workflow version/source commit and the selected world revision
with the operation's internal checkpoint.

## Research and spar in the chat

For research or sparring without an addition request, answer and refine normally.
Do not read the world, request its organization, probe write capability or submit
findings just because Resolvent is selected. Browse for topic evidence when the
request/host requires it. Distinguish sources from assumptions and new analysis.
The user may later ask to add selected findings or distill the discussion.

## Build context or ask the model

Resolve the world under installed client rules. Read its ontology and relevant
canonical records at an admitted/default-branch revision; pending contributions
are not admitted facts. Start with relevant claims/questions, then expand to linked
evidence, sources, joint premises and dependency/coupling context. Use an approved
repository query interface if available; otherwise read canonical YAML and links.
Basic retrieval requires no database, generated knowledge package or shell.

For context, return a compact briefing of relevant statements, assumptions,
uncertainties and gaps. For a question, answer from the recorded evidence and identify
what it does not settle. Preserve source access, disputed accounts and retirement.
For “what applied then”, show unknown/disputed applicability separately; publication
and admission are different clocks. Cite native record IDs/paths and the pinned
revision. Label new reasoning as analysis; do not save it without a request.
A bounded file search does not establish exhaustive graph coverage.

## Research and add

A request to research and add authorizes necessary reads and the selected contribution.
Use **bundled** `references/CONTRIBUTION.md` and its supporting references together
with the world's approved base contracts. Infer the brief, investigate primary sources
and counterexamples, preserve uncertainty, prepare normalized input and complete
admission, genuine independent review, current CI and the authorized ordinary merge.
Do not make the user manage schemas or routine decomposition.

The bundled contribution procedure applies only to an authorized write. Its phrase
“contributing useful findings” does not authorize capturing other turns. “Research X”
alone is not “research and add X”. A later addition may reuse inspected sources; do
not mislabel retrospective work as prospectively designed research.

## Distill selected discussion

Infer whether “distill this” means a chat summary or a model contribution from actual
context. Ask if that distinction or capture span is unclear. Do not assume all history
or an automatic since-last-capture boundary. Use selected visible discussion and
available excerpts/attachments only; mark missing or summarized earlier context as
partial. Capture performs no new topic research.

Use the conversation route with null brief and
`method_metadata.new_research_performed: false`. Attribute human insights, decisions,
assumptions, objections and questions with visible message/quote anchors. Assistant
prose is not independent observation. Distill supported atomic claims with limitations;
retain unresolved questions without forcing assertions. Apply the same admission and
independent review as other writes. Capture again only when asked; link a genuine
continuation to its prior run and preserve immutable identities and idempotent retries.

## Reformulate a question

Read [REFORMULATE.md](REFORMULATE.md) and its listed operators. Produce exactly three
materially different directions, preserving the user's concern and conditions. This
conceptual work neither reads nor writes the model unless requested. No second plugin,
account or server is needed.

## Add a selected question

Resolve which question(s) the user selected, clarifying only ambiguity. Use the
conversation route to preserve original wording, selected formulation, conditions
and visible provenance in the contribution. Add `questions` candidates with local
IDs and justified existing `claim_ids`; an empty `claim_ids` list is valid. Questions
are not claims, so do not fabricate an assertion to justify one.

Question-only input may have empty `claims`/`connectors`, an explicit
`handoff.no_claims_reason`, and empty claim dispositions/connection assessments.
Apply the world's actual schema, admission and closure requirements. The retained
contribution preserves reformulation lineage without expanding canonical Q fields.
Report actual pending/merged status, never an unverified addition.
